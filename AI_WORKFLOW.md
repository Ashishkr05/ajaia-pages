# AI workflow

I used OpenAI Codex throughout this time-boxed project. It helped scaffold the Node server and browser editor, connect document and sharing flows, add the PostgreSQL deployment path, and draft focused automated tests and delivery notes. That saved implementation time, but I made the product and delivery decisions: keep a single-origin app, support seeded demo identities instead of a full auth system, import a safe Markdown subset, and use Postgres for hosted persistence.

I treated generated code as a draft and exercised the product flows. During a manual import attempt I found an `escapeHtml is not defined` error, reported it, and had Codex fix the missing helper. I kept the import format intentionally limited and required raw HTML to be escaped rather than claiming full Markdown compatibility. For deployment, I asked for the health endpoint to identify its storage mode; it now reports `postgres` only when the production service can reach the database. The mock account selector is documented as a demo convenience, not a security boundary.

With Codex, I ran six passing `node --test` tests covering document rules, Markdown conversion, sanitization, sharing permissions, API behavior, local persistence, and response headers. I reviewed the deployed editor in the browser; Codex checked that the live page and document-list API respond and that `/api/health` returns `{"ok":true,"storage":"postgres"}`. This is a small single-instance demo: it has no real authentication or simultaneous editing, and those limits are documented rather than hidden.
